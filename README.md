# PhonePulse（暂定名）

![PhonePulse：iPhone 的网速、充电功率、CPU 一眼看清，切到其他 App 网速还能悬浮显示](docs/cover.png)

看一眼桌面就知道手机状态：**主屏幕小组件**和**灵动岛**是主角，App 负责首次设置、自定义展示内容和查看详细参数。

## 先说清楚：iOS 能做什么、不能做什么

iOS 沙盒很严格，安卓上理所当然的功能在 iPhone 上要么做不了，要么只能变通。产品设计和宣传都要以此为准，否则会被审核拒绝，或被用户差评。

### 参数可行性

来源说明：**实测** = 实时读取的整机数据；**估算** = 根据实测数据推算；**规格** = 机型静态参数（内置表）；**手动** = 用户从系统设置抄过来；**计算** = 由其他数值算出；**仅本 App** = 只代表 PhonePulse 自己，不是整机。

| 类别 | 参数 | 来源 | 实现方式 / 说明 |
|---|---|---|---|
| 电池 | 剩余电量 % | 实测 | `UIDevice.batteryLevel`（1% 还是 5% 一档待真机确认） |
| | 充电状态、低电量模式 | 实测 | `UIDevice.batteryState`、`ProcessInfo` |
| | 设计容量 mAh | 规格 | 内置机型表 |
| | 最大容量 %（电池健康） | 手动 | ❌ App 读不到，用户从「设置 → 电池 → 电池健康与充电」填写 |
| | 当前满电容量 mAh | 计算 | 设计容量 × 最大容量 % |
| | 剩余电量 mAh | 估算 | 当前满电容量 × 电量 % |
| | 循环次数 | 手动 | ❌ App 读不到，iPhone 15 及以后在「设置 → 通用 → 关于本机」可看到 |
| | 电池温度 | ❌ | 没有公开 API |
| 充电 | 充电 / 耗电速度（%/h） | 估算 | 根据电量变化推算：App 打开时分「正在采集 → 初步估算 → 较稳定」三步，快充约 1 分钟出初步结果；小组件靠历史曲线推算 |
| | 充电功率 W | 估算 | 速度 × 满电容量 × 3.85V，是电池净充入功率，不等于充电头功率；保留两位有效数字 |
| | 预计充满时间 | 估算 | 按当前速度推算；优化充电会在 80% 左右放慢 |
| | 电压、电流、充电协议 | ❌ | 只有私有 API（IOKit），用了会被拒 |
| | 充电趋势曲线 | 估算 | App 打开时每秒一个点；关闭时小组件每次刷新记一个点 |
| CPU | 整机使用率 | 实测 | `host_statistics`；读不到时退回「仅本 App」（待真机确认） |
| | 核心数 | 实测 | `activeProcessorCount` |
| | 频率 | ❌ | 没有公开 API |
| GPU | 使用率 | ❌ | 没有任何公开 API |
| | 芯片型号、GPU 核心数 | 规格 | 内置机型表 |
| 内存 | 总量、已用、可用（整机） | 实测 | `physicalMemory`、`host_statistics64` |
| | App 自身占用 | 仅本 App | `task_info` |
| 存储 | 总容量、可用空间 | 实测 | `URLResourceValues` |
| 网络 | 连接类型 | 实测 | `NWPathMonitor` |
| | 上传 / 下载速度 | 实测 | App 打开时每秒；小组件只在刷新时测 1 秒 |
| | 延迟、主动测速 | — | 不做：需要自建测速服务器，只保留实时网速 |
| | 低数据模式、是否按流量计费 | 实测 | `NWPath.isConstrained / isExpensive`（待做） |
| | 蜂窝制式（5G/4G） | 待验证 | `CTTelephonyNetworkInfo` |
| | 信号强度、运营商名称 | ❌ | 不开放；运营商名称 iOS 16 起返回空 |
| 发热 | 温控状态 | 实测 | `thermalState` 4 档：正常 / 偏高 / 高 / 严重；「高」及以上系统会降低性能 |
| | 温度数值 | ❌ | 没有公开 API |
| 其他 | 机型、系统版本、是否有灵动岛 | 实测 / 规格 | |

### 显示位置与刷新

| 方式 | 实时性 | 状态 |
|---|---|---|
| 主屏幕小组件（小 / 中 / 大） | 系统按刷新额度调度，通常 15–60 分钟一次；每次刷新时小组件**自己读取当下数据**，不依赖 App；点小组件上的刷新按钮立即更新 | ✅ 真机验证通过 |
| 锁屏小组件（圆形 / 矩形 / 单行） | 同上 | ✅ 真机验证通过 |
| 灵动岛 / 锁屏实时活动 | App 在前台或悬浮窗开着时，和悬浮窗用同一份数据，显示内容一变就推送（最快每秒一次）；App 被挂起后显示最后的数据并标「已暂停」，充满倒计时由系统自己走动；最长 8 小时 | ✅ 真机验证通过 |
| 画中画悬浮窗 | 每秒刷新，最接近安卓的悬浮网速 | ✅ 真机验证通过；审核有风险，国区已有同类上架 |
| App 内仪表盘 | 每秒刷新 | ✅ |
| 修改系统状态栏 | ❌ | iOS 不允许 |

> 结论：iOS 不允许第三方 App 在后台持续运行，所以小组件和灵动岛做不到安卓那样的"永远实时"。设计上用三个办法弥补：每处都显示更新时间、小组件上有一键刷新、灵动岛的充满倒计时让系统自己走动。
> 国区 App Store 已有不少同类产品（搜"网速""悬浮窗""电池"），要靠小组件和灵动岛的视觉、以及悬浮窗做出差异。

数据流：
- App 打开时：`各 Monitor` → `MetricsEngine`（每秒采样）→ 界面、悬浮窗、灵动岛（`LiveActivityService` 按节奏推送）、充电记录（`ChargeSessionStore`，约每分钟一个点）
- 小组件刷新时：`WidgetSampler` 自己读取电量、存储、内存、温控，CPU 和网速测 1 秒，电量历史存在小组件自己的存储里

## 主屏幕小组件

- **尺寸**：主屏幕小 / 中 / 大，锁屏圆形 / 矩形 / 单行。
- **展示预设**：概览（默认）、极简、电池、充电、性能、网络、自定义。长按小组件 →「编辑小组件」切换；选「自定义」可以自己挑指标，第一个大字显示。
- **版式**：每个尺寸只有一个主指标大字显示，其余指标用简短的数字 + 单位；估算值前面带「≈」；底部显示数据更新时间。
- **刷新按钮**：小组件上的 ⟳ 点一下立即重新读取，不用打开 App。
- **大尺寸**额外有 24 小时电量曲线（插电时段黄色）和灵动岛开关。
- **免费账号限制**：没有 App Group，小组件读不到 App 里手动填写的电池健康，功率按设计容量估算。

## 灵动岛

- **开启 / 关闭**：首页顶部的灵动岛卡片、大尺寸小组件上的按钮、首次引导、控制中心按钮（iOS 18 起），或在「快捷指令」里使用「开关 PhonePulse 灵动岛」（可绑定到操作按钮）。
- **重点显示**：自动（插电看电池，否则看网速）/ 电池 / 网速 / 性能，随时切换，不用重新开启。
- **收起时**：左边电量（或下载速度、CPU），右边充满倒计时（或功率、上传速度、温控）。
- **展开后**：电量环、功率或网速、充满倒计时和进度条、上下行 / CPU / 温控四项小数据、状态（实时 / 已暂停 / 手动刷新）和更新时间。
- **按钮**（展开区和锁屏上）：「刷新」现场读一次数据并更新；「切换」在自动 → 电池 → 网速 → 性能之间切换。点按钮时系统会在后台短暂唤醒 App 执行，不用打开 App。App 正在采样时「刷新」直接推送最新数据；App 被暂停时现场测 1 秒，充电速度和功率沿用上一次的估算。这两个操作也能在「快捷指令」里使用。按一次只更新一次，不会恢复持续实时。
- **没有灵动岛的机型**：显示在锁屏上，内容相同。
- **刷新规则**：见下方「后台运行与刷新」。App 停止采样时会把状态标为「已暂停」，超过 5 分钟没更新标记「可能已过期」。

**小组件和灵动岛真机验证清单**：

- [ ] 点 ⟳ 后更新时间变成当前时间
- [ ] 不打开 App 放置几小时，记录小组件实际多久刷新一次（看更新时间）

- [ ] 锁屏添加三种小组件，显示正常

## 后台运行与刷新

**架构**：`MetricsEngine` 是唯一的数据源，每秒采样一次，同一份结果分发给 App 页面、悬浮窗、灵动岛和充电记录（`MetricsEngine.distribute`）。各处显示的是同一秒的数据，不存在"各自采集、互相不同步"的问题。

**灵动岛以前为什么比悬浮窗慢**：数据源本来就是同一份，慢在推送规则——以前网速模式每 2 秒才推一次，电池和性能模式每 10 秒才推一次。现在改成和悬浮窗一样跟随每秒采样，显示内容一变就推送；内容没变时每 15 秒推一次刷新「更新时间」；上一次还没处理完时只保留最新的一份，不会积压。系统处理一次更新要多久，在诊断页「灵动岛」一栏可以看到。

**「App 在后台持续采集」能做到什么程度**：iOS 不允许普通 App 在后台一直运行。离开 App 后几秒内系统就会把它暂停，暂停后既不能采集，也不能更新灵动岛。目前唯一合规、能让本 App 在后台持续运行的方式是画中画悬浮窗（系统把它当作在播放视频）。

| 情况 | App 能否采集 | 悬浮窗 | 灵动岛 | 小组件 |
|---|---|---|---|---|
| App 在前台 | ✅ 每秒 | 每秒 | 内容一变就更新（最快每秒） | 按系统额度刷新，App 会顺便请求刷新 |
| 离开 App，悬浮窗开着（显示或拖到边缘收起） | ✅ 每秒 | 每秒 | 同前台（待真机确认系统是否限流） | 按系统额度 |
| 离开 App，悬浮窗关着（或设置为离开时不显示） | ❌ 几秒内被暂停 | — | 停在最后的数据，标「已暂停」；充满倒计时仍会走；5 分钟后标「可能已过期」 | 按系统额度，刷新时自己读取当下数据 |
| 锁屏 | 待验证（悬浮窗看不见时系统可能暂停 App） | — | 同上一行或同前台，看真机结果 | 同上 |
| 灵动岛最长显示 | — | — | 8 小时后系统自动结束 | — |

**做不到的，以及原因**：
- **隐藏悬浮窗的同时让灵动岛保持实时**：隐藏悬浮窗后 App 会被暂停，没有其他合规方式让它继续运行。用静音音频、持续定位等方式"保活"会被审核拒绝。
- **只在「回到桌面」时隐藏、在「其他 App 里」显示**：iOS 不告诉 App 用户去了桌面还是别的 App，两种情况对 App 来说都是"进入后台"。所以开关的实际含义是「离开 App 时显示悬浮窗」。
- **服务器推送更新灵动岛**：需要付费账号和服务器，而且服务器拿不到手机的网速、电量，没有意义。

**可落地的替代方案**：
1. **想要灵动岛实时、又不想悬浮窗挡画面**：保持「离开 App 时显示悬浮窗」开启，把悬浮窗拖到屏幕左右边缘收起。收起后它仍在"播放"，App 继续运行（待真机确认）。
2. **只关心充电**：灵动岛的充满倒计时和进度条由系统自己走动，App 被暂停后也会继续变化。
3. **偶尔看一眼**：点灵动岛上的「刷新」按钮，App 会被短暂唤醒读一次最新数据；小组件每次刷新会自己读取最新数据，点小组件上的 ⟳ 立即刷新。

**为什么音乐 App 能在灵动岛上实时更新**：它在后台真的在播放声音，这正是后台音频模式的用途，系统让它一直运行；进度条是系统根据播放位置自己推算的，播放控制也是系统统一提供的界面。本 App 没有声音可放，播放静音来保活会被审核拒绝。

**「离开 App 时显示悬浮窗」开关实际影响什么**：
- 开（默认）：离开 App 时悬浮窗自动弹出或继续显示（自动弹出还需要系统设置里打开「自动开启画中画」）；App 在后台继续采集，灵动岛保持实时。
- 关：离开 App 时悬浮窗不弹出，已开着的也会收起；App 随后被暂停，灵动岛显示「已暂停」。在 App 里时，悬浮窗和灵动岛都不受影响。
- 灵动岛的开启、关闭本身不依赖悬浮窗，依赖的只是"后台能不能继续更新"。

**后台刷新真机验证清单**（每项测完在诊断页复制报告）：
- [ ] App 打开时：灵动岛网速和悬浮窗、App 页面的数字基本同步（相差不超过 1–2 秒）；诊断页「最近 60 秒推送」在网速变化时接近 60 次
- [ ] 回到桌面（开关开）：悬浮窗和灵动岛都继续每秒变化
- [ ] 切到其他 App（开关开），比如边看视频边观察：同上
- [ ] 把悬浮窗拖到屏幕边缘收起：灵动岛是否仍在每秒变化
- [ ] 开关关，回到桌面：悬浮窗收起；灵动岛显示「已暂停」，数字不再变化
- [ ] 锁屏 1 分钟再解锁：看事件日志和「后台最大间隔」，判断锁屏期间 App 是否被暂停
- [ ] 诊断页「系统处理一次更新」通常是多少秒

## 充电体验（第五轮第一批）

- **横屏充电大屏**：插电时首页顶部出现「正在充电」卡片，点「充电大屏」进入。横屏、纯黑背景，大字显示电量、≈功率、充电速度、预计充满时间和本次充电曲线。只有这个页面保持屏幕常亮，离开就恢复自动锁屏；内容每分钟轻微挪动位置，减轻烧屏。设置里可以打开「插电时自动打开充电大屏」（只在 App 开着时生效）。
- **单次充电报告**：从插电到拔电记成一条（「充电」页 →「充电记录」，或上次充电卡片）。包括起止电量、用时、平均和峰值估算功率、曲线、是否疑似进入优化充电（80% 左右明显放慢），以及「数据完整度」：这段时间里有多少比例 App 正在记录。没看到插电或拔电那一刻时，如实写「之前」「约」，用时前加「≥」。
- **待机显示（StandBy）**：小尺寸小组件在系统去掉背景时（待机显示就是这样）自动换成大字版式，只留主指标。夜间红色模式下靠白字的明暗对比保持可读。想在待机时看充电信息，把小组件预设选成「充电」。
- **数据限制**：App 只在运行时记录。免费安装方式没有 App Group，App 读不到小组件记录的电量点，所以 App 关闭期间的充电过程补不上；开通付费账号后可以合并。记录只保存在手机本地（Application Support/ChargeSessions.json）。

## 第六轮：细节打磨

### 充电功率：更快测出可信的结果

**数据来源**：iOS 只给 App 电量百分比和充电状态（实测），不开放电压、电流。界面上的「充电功率」一律是**估算**：速度 × 满电容量 × 3.85V。

**为什么要等**：电量是取整的（1% 或 5% 一档）。只有「电量刚变化的那一刻」时间是准的，所以至少要看到两次电量变化才能算出速度。这部分由系统数据精度决定，无法再缩短。

**这一轮改了什么**（`Core/BatteryPowerEstimator.swift`）：
- 分三步显示：**正在采集**（还没看到两次变化，说明在等什么）→ **初步估算**（两次变化、跨度 ≥ 36 秒）→ **较稳定**（≥ 3 次变化、跨度 ≥ 2.5 分钟）。以前要求跨度 ≥ 60 秒才出结果，而且不区分阶段。
- 快充时只用最近 3 分钟的变化点，速度变了能更快跟上（以前固定用 15 分钟平均）。
- **已放缓**：电量比平时久得多没变（比如 80% 后的优化充电），不再沿用之前的高速度，只显示上限（如「≤ 1 W」），也不再算出错误的充满时间。
- **插拔、暂停不沿用旧结果**：插拔充电器立即开始新一轮；App 被暂停后回来，第一个读数只当起点（以前会把它当成「刚变化」，算出偏低的速度）；暂停超过 2.5 分钟或回来时电量反向变化，重新开始一轮。
- 显示结果更新时间（如「12 秒前更新」）；功率保留两位有效数字（18 W、4.3 W），因为电压按 3.85V 计、容量按手动填写，本身有约 ±10% 误差。
- 首页充电卡片、电池详情、充电大屏、灵动岛用同一套状态说法（`Shared/PowerReadout.swift`）：正在采集 / 初步估算 / 较稳定 / 已放缓 / 已断开 / 暂无数据 / 已充满。专业解释放在电池详情的「怎么测的、准不准」里。

**等待时间（按 3300 mAh 电池计算的平均值）**：

| 场景 | 每变一档约 | 优化前首个结果 | 优化后初步估算 | 较稳定 |
|---|---|---|---|---|
| 1% 一档 · 25 W | 18 秒 | 约 82 秒 | 约 46 秒 | 约 3 分钟 |
| 1% 一档 · 20 W | 23 秒 | 约 80 秒 | 约 57 秒 | 约 3 分钟 |
| 1% 一档 · 10 W | 46 秒 | 约 114 秒 | 约 69 秒 | 约 3.5 分钟 |
| 1% 一档 · 5 W | 91 秒 | 约 137 秒 | 约 137 秒（不变） | 约 4 分钟 |
| 5% 一档 · 20 W | 114 秒 | 约 3 分钟 | 约 3 分钟（不变） | 约 5 分钟 |
| 5% 一档 · 5 W | 7.6 分钟 | 约 11 分钟 | 约 11 分钟（不变） | 约 19 分钟 |

第一次电量变化什么时候来是随机的（0 到一档间隔之间），表里按平均算。慢充和 5% 一档时，两次电量变化之间本来就超过 36 秒，所以没法更快。仍受系统影响的部分：系统多久更新一次电量值（诊断页「最近变化间隔」可以看出来，间隔忽大忽小说明有延迟）。

### 控制中心按钮（iOS 18 起）

- **灵动岛开关**、**刷新手机状态**、**切换灵动岛内容**三个按钮（`Widget/StatusControls.swift`），也可以放到锁屏底部或绑定操作按钮。
- 执行的意图和灵动岛、小组件上的按钮是同一套，由系统在 App 进程里执行，走 `LiveActivityService` 的同一套逻辑，三处状态一致。「刷新」同时让小组件重新读取；「切换」在灵动岛没开时先开启。
- **为什么灵动岛用按钮不用开关**：开关要在扩展里读到「灵动岛开着没有」，扩展读不到 App 的实时活动，只能靠 App Group；免费账号侧载时 App Group 不可用，开关会一直显示「关」。所以用按钮：App Group 可用时名称显示当前状态（「结束灵动岛」「灵动岛：电池」），不可用时显示通用名称，点一下灵动岛出现 / 消失就是反馈。诊断页会显示 App Group 是否可用。
- 首次使用：首页灵动岛卡片里有一次性提示，设置 →「添加控制中心按钮」有步骤。
- 最低系统仍是 iOS 17：扩展入口按系统版本选择带不带控制中心按钮的两套组件。

### 充电器／线材对比档案

- 给配件组合起名（如「床头充电器＋白色线」），在「充电」页或充电报告里一点就能选；常用的排前面，没选时首页和充电页都有「还是用上次的」一键选择。设置里可以打开「新的充电沿用上次的配件组合」（默认关，避免换了充电器忘改导致对比不准）。
- 对比（「充电」页 → 充电器／线材对比）：自动找两组记录都完整覆盖的同一段电量区间（至少 10 个百分点，优先 80% 以下），用「刚涨到下限」到「刚涨到上限」的真实时间；只用 App 实际在记录的连续数据。展示区间用时、电量增长速度、估算功率（标「≈」），以及全部记录的常见起止电量和单次时长。
- 每组取中位数；每组至少 2 次记录才下结论，差别小于 10% 算「差不多」；不够时显示「数据不足，继续记录」或「初步数据」。记录充电期间的最高温控，有发热时提醒可能被限速。
- 删除组合不会删除记录，只是改回「未指定」。

## 第七轮：充电页与充电结论

**为什么改**：前几轮功能不少，但 App 实际只有一个首页加设置，充电记录、配件对比、充电报告都藏在「插电时的首页卡片」和设置里，不充电时完全看不到；首页说明文字大多在讲限制。iOS 能读到的电池数据就那几项，再加数字意义不大，所以这一轮不加新的采集，而是把已有的东西摆出来，并把数字解读成结论。

**标签页**：状态 / 充电 / 设置（移除主动测速：需要自建服务器，只保留实时网速）。

- **状态（首页）**：只放「现在」。插电时顶部是简要充电卡片（电量、≈功率、测定状态、迷你曲线，「充电大屏」「充电详情」两个按钮，没选配件时有「还是用上次的」）；其下网速、悬浮窗、CPU / 内存 / 电池 / 存储、灵动岛、设备。灵动岛和悬浮窗卡片的说明缩短，限制说明留在引导和 README。
- **充电**：
  - 充电时：大号电量、≈功率和测定状态、带坐标轴的本次曲线、选配件、「充电大屏」「本次报告」。
  - **和平时比**（`Core/ChargeInsights.swift`）：在这次和以往记录都完整覆盖的同一段电量区间里比速度（区间选法同配件对比：至少 10 个百分点、优先 80% 以下，且尽量让 2 条以上以往记录可比）。差别小于 10% 算「差不多」；慢了会给可能原因（发热限速 / 换了充电器或边充边用）。以往可比记录少于 2 条时，充电中不显示，上次充电卡片上显示「还不能和平时比」和还差几次。
  - **上次充电**：起止电量、用时、平均 ≈功率、配件、迷你曲线，标出疑似优化充电、发热、完整度偏低；点进去是完整报告。
  - **充电习惯**（≥ 3 条记录）：通常从多少充到多少、一次多久；超过一半在同一时段插电时显示「常在晚上开始充电」（只用看到插电那一刻的记录）。不足 3 条时显示进度。
  - **近 7 天**：充了几次、App 记录到共充入多少（约几次满电）；经常充到 100% 时提醒打开系统的优化充电或充电上限（夜里充电的人措辞不同）；有疑似优化充电时说明「是系统在保护电池，不是充电器坏了」；有发热时提醒。
  - **记录与对比**：充电记录（条数）、充电器／线材对比（最近两个组合的一行结论）、管理配件组合。
  - 没有任何记录时：说明插电开着 App 就会记录，并预告报告、和平时比、配件对比、充电大屏分别能看到什么。
- **设置**：充电相关只留两个开关；充电记录和对比的入口移到充电页。
- 「插电时自动打开充电大屏」改到最外层处理，不管当前在哪个标签都生效（首次引导没完成时不弹）。

**第七轮真机验收清单**：

## 悬浮网速窗（画中画）

iOS 不允许 App 在别的 App 上面画东西，但允许"画中画播放视频"。做法是：

1. `MetricsEngine` 每秒采样后通过 `onTick` 通知 `FloatingSpeedController`
2. `SpeedFrameRenderer` 把网速画成一帧图像（CVPixelBuffer → CMSampleBuffer）
3. 这一帧送进 `AVSampleBufferDisplayLayer`，再由 `AVPictureInPictureController` 用画中画显示
4. 画中画开着时系统让 App 在后台继续运行，所以采样和刷新不会停

前提条件：
- Info.plist 声明 `UIBackgroundModes = audio`（"音频、AirPlay 和画中画"后台模式），已在 `project.yml` 里配置好
- 音频会话设为 `playback` + `mixWithOthers`，不会打断用户正在听的音乐
- 视频源图层必须显示在界面上，所以仪表盘里有一块预览卡片

**真机验证清单**（模拟器上画中画行为和真机不一样）：
- [ ] 点"开启悬浮窗"能弹出悬浮窗
- [ ] 切到其他 App，悬浮窗里的网速每秒刷新（比如边看视频边观察）
- [ ] 留在仪表盘时直接上滑回桌面，悬浮窗自动弹出（需在 设置 → 通用 → 画中画 打开"自动开启画中画"）
- [ ] 关闭悬浮窗后 App 能正常停止采样，不再后台耗电
- [ ] 开着悬浮窗 30 分钟，在 设置 → 电池 看耗电是否可以接受
- [ ] 用手机放音乐时开启悬浮窗，音乐不被打断

**已知限制**：画中画上会有系统自带的播放/暂停按钮（没有公开 API 能隐藏），点了也没影响；悬浮窗大小和位置由系统控制。

## 怎么编译

iOS App 只能在 macOS + Xcode 上编译。在 Windows 上开发有三条路：

1. **GitHub Actions（免费，先用这个）**：把项目推到 GitHub，每次 push 会在云端 Mac 上自动编译并运行单元测试，但装不到手机上。
2. **云 Mac**（MacinCloud 等，按小时租）：编译后上传 TestFlight，再装到自己的 iPhone 上。
3. **买或借一台 Mac**（二手 M1 Mac mini 就够）：最顺手，可以直接连 iPhone 调试。

在 Mac 上：

```bash
brew install xcodegen
xcodegen generate
open PhonePulse.xcodeproj
```

然后在 Xcode 里选择你的 Team，连上 iPhone 运行。很多指标（电量、CPU、网卡流量）在模拟器上没有意义，必须用真机测。

上架和 TestFlight 需要付费的 Apple Developer 账号（国区 688 元/年），小组件读主 App 数据用的 App Group 也需要它。

### 免费真机安装（不需要 Mac，也不需要付费账号）

云端打出未签名的安装包，再在 Windows 上用 [Sideloadly](https://sideloadly.io) 配合免费 Apple ID 签名安装。适合真机验证和自己日常使用，**不能用来上架**。

**准备（只做一次）**
1. **专门注册一个新的 Apple ID 用来侧载，不要用主账号**：Sideloadly 是第三方闭源工具，需要输入账号密码。
2. 从 Apple 官网下载安装 Windows 版 iTunes 和 iCloud（Sideloadly 要求官网版本，不要用 Microsoft Store 版）。
3. 只从 sideloadly.io 官网下载安装 Sideloadly。
4. iPhone 用数据线连电脑，手机上点「信任此电脑」。

**每次安装**
1. 在 GitHub 仓库打开 Actions → 左侧选「Sideload IPA」→「Run workflow」。几分钟后在这次运行页面底部下载安装包（下载的是 zip，解压后得到 `PhonePulse-unsigned.ipa`）。
2. 打开 Sideloadly，选择这个 ipa，填入专用 Apple ID，点 Start，按提示输入密码和验证码。
3. 第一次安装后，在 iPhone 上：设置 → 通用 → VPN 与设备管理 → 信任这个 Apple ID；再打开 设置 → 隐私与安全性 → 开发者模式（需要重启）。

**限制**

## 上架注意事项

- 充电功率必须标注"估算"，不要宣传"精准测量充电瓦数"。
- 不要用后台音频、定位等模式"保活"来实现后台实时刷新，会被拒。悬浮窗声明的 audio 后台模式只用于画中画，审核备注里要写清楚用途。
- 不要调用私有 API（例如用 IOKit 读电流电压），会被拒。
- 隐私清单 `PrivacyInfo.xcprivacy` 已声明用到的"需说明原因的 API"（App：磁盘空间、系统启动时间、UserDefaults；小组件：磁盘空间、UserDefaults）。
- 电池健康、循环次数只能由用户手动填写，界面上要标「手动」，不要暗示是自动读取的。
